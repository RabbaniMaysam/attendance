# Attendance

A web page where students mark themselves present during class and answer in-class questions, with an instructor page for the schedule, the grid of marks, the questions, the points, and the log.

- `docs/` holds the two pages, served by GitHub Pages: `attendance.html` for students (link `attendance.html?c=key`) and `attendance_admin.html` for the instructor.
- `worker/` is the backend, a Cloudflare Worker with a D1 database.
- `backup/` has the daily dump of the database and its restore notes.
- `test/` holds the checks (see Tests).

No student data is stored in this repository. Each class's roster, marks, answers, and activity log are in the database.

The tool was part of the group sign-up tool (RabbaniMaysam/group-signup) until 2026-10-05, when it became this repository with its own Worker and database. The old page addresses there forward to the pages here.

## How it works

An attendance class has its own roster, weekly class days with an opening and a closing clock time (New York time), optional first and last class days, holidays (a new class starts with the Fall 2026 schedule in `DEFAULT_SCHEDULE` and `DEFAULT_SKIP` of `worker/src/attendance.js`), and one-off windows ("Open attendance now for N minutes"; "Close attendance now" ends the open window at the current minute). Every window is one attendance round, identified by its date and opening minute, and marks are stored per round: opening attendance three times in a day records three rounds, each a column in the grid, and every student can mark again in each new round ("Open now" while a round is open closes that round and starts the next). A student signs in, types the 4-digit session code, and presses one button while a round is open; the mark is refused outside a round or with a wrong code, and a wrong code can be retried without limit. The session code is shown wherever the QR code is (the QR code tab and the QR tab opened from it) and changes every 6 seconds, like a two-step verification code, with a bar that empties over the code's 6 seconds: the Worker derives the code from a per-class secret and the 6-second slot of the server clock, the instructor page computes the same code from the secret it is sent, and the Worker accepts the current code and the previous one (6 to 12 seconds of validity), so a code relayed to someone outside the room is stale by the time it arrives. The Settings tab can switch codes off. An open round, scheduled or one-off, can be extended by a number of minutes while it is open. The instructor page shows the time left in the open window (mm:ss) and a QR code of the student link, on its own tab, with the session code and the live status of attendance and questions; "Open in a new tab" opens that screen as a separate browser tab (`attendance_admin.html?qr=key`) to drag to the classroom projector while the instructor page stays on the other monitor, and every tab opened this way shows the same QR code and session code (both derive from the class and the server clock). The instructor page shows a students-by-rounds grid (refreshed every 10 seconds; a switch shows today's rounds or every round; the grid is as narrow as its content, with every header vertical; several rounds on one day are several columns with the same date label), and downloads the grid as CSV. An "Exclude dates" checkbox shows a row of checkboxes under the date headers, one per round, all checked: unchecking a date (after a confirmation, saved at once) excludes it, so its column is hidden and its rounds count in no percentage or points until it is checked again; its marks are kept. The Reports tab excludes and includes dates too. A "Remove rounds" checkbox shows a row of red checkboxes, one per round, all checked: unchecking a round (after a confirmation) deletes it outright with its marks, for a trial run of attendance; a one-off window is removed, and a scheduled round is listed under Settings until it is restored. Opening attendance twice within one minute reopens the same round (the round is identified by its opening minute), and the "Open now" confirmation says so when it applies. Cells are locked while a round is open; afterwards any cell can be switched by hand, changes stay pending until "Save" (or are dropped with "Don't save"), and leaving the tab, the class, or the page asks first. A manual change is recorded next to the student's own mark: each cell carries a change value of +1 (marked present by the instructor), -1 (marked by the student, set absent by the instructor), or 0 (the value equals what the student did, also after a change is undone). The grid colors changed cells, counts each student's changes, lists every change with its time below the grid, and the CSV has a change column beside each round.

Attendance points are set on the Settings tab, either per class meeting (for example 0.2 per round marked present) or as a semester total that is divided equally over every session from the first to the last class day (scheduled days minus holidays, plus one-off windows), so a perfect record over the first 4 of 28 sessions earns 4/28 of the total. A session with several rounds splits its points among them. The Reports tab lists each session (rounds, present counts, share of the roster, points) and each student (rounds present, percentage, points earned, points possible so far, semester points), both as CSV. The Log tab records every action with its time and account (windows opened and closed, marks and manual changes, questions, roster changes, settings), filterable to the instructor's actions, the students' actions, or everything, with a search box and CSV. The log is also where refused requests are listed, including a page load by an account that is not on the roster, and each Google sign-in on the student page (later visits use the session token, so a student's sign-ins are rare). "Download everything" (Reports tab) saves one JSON file with the class's settings, roster, marks, answers, and log; the page reminds the instructor after 60 days without one.

The student page is a lobby: it stays open during class and refreshes itself (every 8 seconds from the window's opening for two hours, every 3 seconds while a question is open, otherwise every 30 seconds or at the next opening if sooner; a hidden tab does not poll). Besides attendance, the instructor asks in-class questions from the Questions tab: True/False, Yes/No, multiple choice with 2 to 5 lettered choices, or an open answer (a text box for a number, a word, or a sentence, up to 500 characters), with optional text, an optional correct answer, and a closing time (default 2 minutes). Students answer with one press (or type and press Submit) and may change the answer until the question closes; answers are named. The instructor sees live counts per choice (for an open question, per distinct answer, most frequent first) and each student's answer, can close, extend, or reopen a question, set the correct answer later, and download a students-by-questions CSV. The correct answer of an open question is free text; an answer counts as right when it equals it ignoring case and spacing, or as a number ("1,500.0" equals "1500"). Once a question closes, students see the correct answer if one was set.

Rules are in `worker/src/attendance.js`; storage is the `att_classes`, `att_marks`, `att_answers`, and `log` tables (the log's class column is `att:` followed by the key). Only the accounts in the Worker's `ADMIN_EMAILS` secret can use the instructor page.

## Roster files

The import (`parseRoster` in `worker/src/roster.js`) reads the Canvas gradebook export, with a "Student" column ("Last, First") and a "SIS Login ID" column (the address before the @, completed with `@montclair.edu`; the "Points Possible" row and Canvas's test student are skipped), or a CSV with first name, last name, and email columns in any order. Addresses are lowercased, and `@mail.montclair.edu` is stored as `@montclair.edu`; a student may sign in with either form. The domain rule is the one line `canonEmail` in `roster.js`. The Roster tab also adds one student by hand, removes one, and edits one ("Edit" on the row): the name, the main address (the marks and answers recorded under the old address are moved to the new one), and any number of other addresses, such as a personal Gmail, that sign the student in as the same person; a sign-in with one of them is recorded under the main address, and an address in use by one student cannot be given to another. Importing a roster keeps the other addresses of the students who stay on it.

## Sign-in

The pages use the "Sign in with Google" button. The Worker verifies Google's signature on the sign-in token and that the token was issued for this tool's client ID, then answers with a session token of its own (signed with the `SESSION_SECRET` secret, valid 180 days), which the page keeps in the browser's storage and sends from then on, so a student signs in with Google once a semester per browser and later only opens the link; "Sign out" deletes the token. Without the secret, the pages fall back to Google's token, which lasts an hour. Changing the secret signs every browser out. The client ID is a public identifier created once in Google Cloud Console (type "Web application", with the page's origin, for example `https://USERNAME.github.io`, under "Authorized JavaScript origins", and the student page's full address, `.../attendance/attendance.html`, under "Authorized redirect URIs"). The redirect URI serves the "Choose or add the university account" link under the button: a browser signed into one personal Google account is signed in with it by the button without a choice, so the link opens Google's account chooser in the same tab (`prompt=select_account`), which returns to the page with the ID token in the address's fragment; the page keeps it only if the nonce it stored before leaving matches. It is the value of `GOOGLE_CLIENT_ID` in `worker/wrangler.toml` (the same client ID as the group sign-up tool). The tool holds no permission on any Google account.

## Deployment

From `worker/`, with a Cloudflare account:

```
npx wrangler d1 create attendance            # once; copy the database_id into wrangler.toml
npx wrangler d1 execute attendance --remote --file schema.sql
npx wrangler secret put ADMIN_EMAILS         # comma-separated instructor emails
npx wrangler secret put SESSION_SECRET       # any long random string (signs the session tokens)
npx wrangler deploy
```

Then write the Worker's address into `docs/config.js`.

## Tests

- `node test/test_attendance.mjs` checks the attendance windows (New York time, clock changes, holidays), settings, roster import, in-class questions, the student view, session dates, the points report, excluded dates, removed rounds, and the session codes (including that the instructor page's copy of the code function equals the Worker's).
- `node test/test_worker.mjs` checks a local copy of the Worker end to end (its header lists the commands).
- `node test/check_pages.mjs` checks that the page scripts parse and reference no undeclared names.
